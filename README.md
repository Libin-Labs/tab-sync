# @libinprasanth/tab-sync

Package version: `1.0.0`. License: MIT.

```sh
npm install @libinprasanth/tab-sync
```

Typed, same-origin tab-to-tab messaging built on `BroadcastChannel`, with
instance IDs, message subscriptions, and explicit cleanup. A transport factory
can be injected for tests or compatible environments.

## Requirements

The default transport requires the browser `BroadcastChannel` API and its
normal same-origin storage partition. The package has no runtime dependencies.
Messages must be structured-cloneable, as required by `BroadcastChannel`.

The manifest requires Node.js 20+ for Node consumers. ESM and CommonJS entry
points have separate declarations. TypeScript uses ES2022 and DOM library
declarations; Node ambient types, React, CSS, and a worker package are not
required. Importing does not create a channel or access browser globals;
construction creates the transport.

## Quick start

```ts
import { createTabSync } from "@libinprasanth/tab-sync";

type AppMessages = {
  "cart:changed": { itemCount: number };
  "session:expired": { reason: "logout" | "timeout" };
};

const sync = createTabSync<AppMessages>("my-app", {
  instanceId: "optional-stable-per-tab-id",
});

const unsubscribe = sync.subscribe("cart:changed", ({ payload, sender }) => {
  console.log(`${sender} has ${payload.itemCount} items`);
});

sync.send("cart:changed", { itemCount: 3 });

unsubscribe();
sync.close();
```

`instanceId` is generated when omitted. `send(type, payload)` returns a unique
message ID. Received messages contain `id`, `type`, `payload`, `sender`, and
`sentAt` (milliseconds from the sender's clock). `subscribe(type, handler)`
receives only one message type; `subscribeAll(handler)` receives every valid
message. Both return idempotent unsubscribe functions. Calling `close()` removes
the transport listener, closes the channel, and clears subscriptions; subsequent
send or subscribe calls throw `TabSyncClosedError`.

## Transports and errors

`TabSyncOptions` accepts `instanceId`, `now` (a clock function), and
`transportFactory(channelName)`. A transport implements `postMessage`,
`addEventListener("message", listener)`, `removeEventListener`, and `close`.
For example, inject a fake transport in tests to assert sender/receiver
behavior without relying on browser globals.

When `BroadcastChannel` is unavailable and no factory is supplied, construction
throws `TabSyncUnavailableError`. `TabSyncError` is the package base error.
Malformed messages, unknown protocol versions, other channel names, and a
message from the instance's own ID are ignored. Handler exceptions are not
silently swallowed. IDs are identifiers, not authentication: do not treat a
message as trusted input.

### Complete public surface

Runtime exports are `TabSync`, `createTabSync`, `TabSyncError`,
`TabSyncUnavailableError`, and `TabSyncClosedError`, all named exports.
`new TabSync<Messages>(channelName, options?)` has the same behavior as
`createTabSync<Messages>(channelName, options?)`. Both expose readonly
`channelName: string` and `instanceId: string`.

Type-only exports:

- `MessageMap = Record<string, unknown>`: a map of string message types to
  payloads. Prefer a concrete type alias like `AppMessages` in the example.
- `SyncMessage<Messages>`: a discriminated union of
  `{ id: string; type: Type; payload: Messages[Type]; sender: string; sentAt: number }`.
- `MessageTransport`: `postMessage(message: unknown): void`,
  `addEventListener("message", listener): void`,
  `removeEventListener("message", listener): void`, and `close(): void`;
  listeners receive `{ data: unknown }`.
- `TabSyncOptions`: optional `instanceId: string` (generated by default),
  `transportFactory: (channelName: string) => MessageTransport` (defaults to
  BroadcastChannel), and `now: () => number` (defaults to `Date.now`).

`send<Type>(type, payload): string` always requires a payload argument, even
when its type permits undefined. `subscribe<Type>(type, handler): () => void`
narrows the envelope to that type. `subscribeAll(handler): () => void` receives
the full union. Subscription does not replay old messages or call immediately.
There is no listener deduplication. Delivery snapshots the current listener set;
an exception stops subsequent listeners for that message. Custom transports
must carry the library's full wire envelope unchanged.

Empty/whitespace channel names or instance IDs throw `TypeError`; empty message
types throw `TypeError` on send/subscribe. Transport creation and structured-clone
errors propagate. `TabSyncError(message, options?: ErrorOptions)` is the base
constructor; its two subclasses inherit that signature. Closing is idempotent.
Use unique per-instance IDs: receivers ignore all messages bearing their own ID.

## Limits

Messages are best-effort broadcasts to currently connected channel peers; this
package does not persist, retry, acknowledge, or guarantee delivery/order
across crashes. It does not elect a leader or coordinate exclusive ownership.
There is no payload schema validation at runtime; validate untrusted payloads in
your handler. Messages are not delivered back to their sender by the
`BroadcastChannel` API.

Unsubscribe and close on application teardown. There is no AbortSignal or
duplicate-message suppression. Large/frequent payloads incur cloning and
listener costs; coalesce updates in your application. This is a non-visual
utility: UI announcements and accessibility belong to the receiving application.
